# Risk Log

## R-024 — Неполная загрузка исходников

**Статус:** контролируется автоматически.

Контроль: workflow `Repository integrity` завершает проверку с ошибкой при отсутствии обязательных компонентов.

## R-025 — Небезопасная production-конфигурация

**Статус:** снижен startup gate.

Риск: приложение может быть запущено в production с HTTP, небезопасной cookie, коротким стандартным admin token, относительной SQLite-базой или общим каталогом для storage и backup.

Контроль: `scripts/check_config.py` вызывается Docker entrypoint до миграций. При `APP_ENV=production` обнаруженная небезопасная настройка завершает запуск с кодом ошибки.

Остаточный риск: проверка конфигурации не заменяет внешний secret manager, TLS termination, ограничение сетевого доступа и ротацию секретов.

## R-026 — Утечка приватных данных через публичный GitHub

**Статус:** снижен CI privacy gate.

Риск: случайный commit `.env`, SQLite-базы, credential-файла, токена, приватного ключа или реального VIN делает данные доступными в истории публичного репозитория.

Контроль: `scripts/check_repository_privacy.py` проверяет обязательную структуру, запрещённые файлы и расширения, известные форматы секретов и возможные 17-значные VIN до миграций и тестов.

Остаточный риск: pattern scan не гарантирует обнаружение всех видов секретов и не удаляет данные из уже опубликованной Git history; при реальной утечке необходимы немедленная ротация и очистка истории.

## R-027 — Неограниченный рост storage владельца

**Статус:** снижен owner-wide quota.

Риск: владелец может загрузить неограниченное число документов через события и сервисные визиты, исчерпав диск приложения или ухудшив время backup/restore.

Контроль: SQLAlchemy listener проверяет количество и суммарный объём активных вложений по всем автомобилям владельца до вставки Attachment. Лимиты задаются `MAX_OWNER_ATTACHMENTS` и `MAX_OWNER_STORAGE_BYTES`; превышение возвращает структурированные HTTP 409/413 ошибки.

Остаточный риск: физический storage остаётся локальным, отсутствуют резервирование дискового пространства и per-plan quotas.

## R-028 — Расхождение квоты и отображаемого usage

**Статус:** снижен единым read model, API и owner UI.

Риск: если enforcement, API и интерфейс используют разные правила, владелец может видеть неверный остаток квоты.

Контроль: `storage_usage_for_owner` используется как единый источник расчёта для listener, сервиса `owner_storage_usage` и аутентифицированного `GET /api/me/storage`. Owner UI отображает серверные значения без самостоятельного пересчёта, обновляется после удаления и показывает предупреждения при 80%/95%.

Остаточный риск: конкурентные загрузки в многопроцессном deployment могут одновременно пройти предварительную проверку до фиксации соседней транзакции.

## R-029 — Потеря PWA-артефактов из-за плоской загрузки

**Статус:** устранён восстановлением `app/static` и тестом структуры.

Риск: FastAPI монтирует `app/static`, поэтому наличие одноимённых файлов только в корне репозитория приводит к ошибкам `/`, manifest, offline shell и service worker.

Контроль: все текстовые и бинарные PWA-артефакты восстановлены внутри `app/static`; `tests/test_storage_ui.py` проверяет обязательный набор файлов.

## R-030 — Неограниченное создание публичных ссылок

**Статус:** снижен owner-wide и per-vehicle quota.

Риск: владелец может создавать неограниченное количество временных ссылок по множеству автомобилей, увеличивая поверхность публичного доступа и объём исторических записей.

Контроль: SQLAlchemy listener считает только активные, неотозванные и неистёкшие ShareLink. Лимиты задаются `MAX_ACTIVE_SHARE_LINKS_PER_VEHICLE` и `MAX_ACTIVE_SHARE_LINKS_PER_OWNER`; превышение возвращает структурированный HTTP 409.

Остаточный риск: конкурентные вставки в многопроцессном deployment могут одновременно пройти предварительный count; для production после SQLite потребуется транзакционный или атомарный счётчик.
